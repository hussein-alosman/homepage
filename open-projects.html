Overview

These are open projects on fast heart rhythms, for Master's (CSI6900) and Honours (CSI4900) students. They use public data only, so a student can start right away.

Each project is split into stages. A student takes on one stage, not the entire multi-stage project. One stage is one student's work for one 4-month semester. When a student finishes a stage, the next student picks up from where they left off.

The projects fall into two areas:

  • Part A: SVT (supraventricular tachycardia). A fast rhythm that starts in the upper chambers of the heart. These projects use ECG recordings.
  • Part B: VT radiation planning. VT (ventricular tachycardia) is a fast rhythm that starts in the lower chambers. It can be treated by aiming radiation at the heart tissue that causes it. These projects use public heart scans and body-surface ECG data.

Part A: SVT projects

A1. Finding SVT Episodes in Long ECG Recordings

SVT episodes come and go, so they are often missed in short clinic visits and have to be found in long recordings. This project builds a detector that marks where fast upper-chamber rhythms start and stop, and compares a simple rule-based method with a small deep learning model.

Expected results: A working episode detector and a fair comparison of the two methods.

Learning outcomes: Basic ECG signal processing, working with expert labels, careful testing of detectors.

Suitability: CSI6900 or CSI4900.

References: MIT-BIH Supraventricular Arrhythmia Database (78 half-hour ECG recordings). MIT-BIH Arrhythmia Database.

Stages (one semester each):

  1. Data and simple detector. Load both databases, check which expert labels support episode start and end times, and build a rule-based detector using heart rate and beat timing. Hand over the data loader, episode labels, scoring script and baseline scores.

  2. Learning-based detector. Train a small deep learning model using the Stage 1 data, and score it with the same Stage 1 script so the comparison is fair. Hand over the trained model and a comparison report.

A2. Telling SVT Apart from Other Fast Rhythms on a 12-Lead ECG

A fast heart rate can have several causes, and telling them apart affects treatment. This project trains a classifier on standard 12-lead hospital ECGs and shows which parts of the ECG the model relies on, so a doctor can check its reasoning.

Expected results: A fast-rhythm classifier, an analysis of its mistakes, and plots showing what drives each decision.

Learning outcomes: Classification with several labels per record, handling rare classes, explaining model decisions.

Suitability: CSI6900.

References: Wagner et al., PTB-XL: A Large Publicly Available ECG Dataset, Scientific Data, 2020 (21,799 ten-second 12-lead ECGs).

Stages (one semester each):

  1. Data check and baseline. Count how many records carry fast-rhythm labels. If there are too few, find and add a second public dataset. Build a basic classifier. Hand over a data report with label counts, a fixed train/test split and baseline results.

  2. Better classifier. Improve the model and deal with rhythms that have far fewer examples than others. Hand over the improved model and results on the same split.

  3. Explaining decisions. Show which parts of the ECG drive each decision, and review a sample of cases with a clinician. Hand over the explanation plots and review notes.

A3. Finding P-Waves Automatically

The P-wave is the small bump on the ECG that shows the upper chambers firing. Its shape and timing are key clues for spotting SVT, but it is small and easily hidden by noise. This project builds a P-wave detector and studies where it fails.

Expected results: A P-wave detector with accuracy figures and a catalogue of failure cases.

Learning outcomes: ECG waveform structure, signal filtering, measuring detection accuracy.

Suitability: CSI6900 or CSI4900.

References: MIT-BIH P-wave Annotations (PhysioNet), expert P-wave labels for twelve signals from the MIT-BIH Arrhythmia Database.

Stages (one semester each):

  1. Detector on clean signals. Build a P-wave detector and test it against the twelve labelled signals. Hand over the detector, scoring script and accuracy results.

  2. Failures and improvement. Catalogue where the detector fails, improve it, and try it on SVT recordings. Hand over the failure catalogue and the improved detector.

A4. How Well Do Rhythm Detectors Handle Noise?

Recordings from wearable devices are much noisier than hospital ECGs, and detectors that work well in the lab can fail in daily use. This project measures how existing open-source rhythm detectors hold up as noise increases, and tests ways to make them more robust.

Expected results: A test bench showing how accuracy changes with noise level, and at least one tested improvement.

Learning outcomes: Robustness testing, experimental design, honest reporting of results.

Suitability: CSI6900 or CSI4900.

References: MIT-BIH Noise Stress Test Database (PhysioNet), which adds measured amounts of real recording noise to clean MIT-BIH recordings.

Stages (one semester each):

  1. Test bench. Collect open-source rhythm detectors and build a test bench that adds noise at increasing levels. Hand over the test bench and results for each detector.

  2. Making detectors more robust. Try simple fixes and measure them on the same test bench. Hand over the fixes and a before-and-after report.

Part B: VT radiation planning projects

B1. Turning Heart Scar Scans into a Standard "Bull's-Eye" Map

To plan radiation for VT, doctors need to see where scar tissue sits in the heart wall. A bull's-eye map flattens the heart wall into a circle, so different patients and scans can be compared side by side. This project builds a pipeline that turns MRI scans with scar outlines into a standard bull's-eye scar map.

Expected results: An open pipeline from scan to scar map, checked against expert outlines.

Learning outcomes: Medical image formats, the 3D shape of the heart, data visualization.

Suitability: CSI6900 or CSI4900.

References: Lalande et al., "Deep learning methods for automatic evaluation of delayed enhancement-MRI. The results of the EMIDEC challenge," Medical Image Analysis, vol. 79, 2022, 102428 (150 MRI exams, 50 normal and 100 with heart attack scarring).

Stages (one semester each):

  1. Heart wall map. Load the EMIDEC scans, find the long axis of the left ventricle, and build a bull's-eye map of wall thickness from the expert outlines. Hand over the pipeline and sample maps.

  2. Add the scar. Add a scar layer and compute the scar percentage in each heart segment, then check the totals against the expert outlines. Hand over the full pipeline and a validation report.

B2. How Much Can We Trust Automatic Heart Wall Outlines?

Radiation planning tools rely on automatic outlines of the heart wall, and any error carries through to the treatment target. This project measures how far automatic outlines are from expert ones, in millimetres, and maps where on the heart wall the errors concentrate.

Expected results: An error map of the heart wall showing where automatic outlines are least reliable.

Learning outcomes: Measuring segmentation quality (overlap and distance), statistics, fair comparison of tools.

Suitability: CSI6900.

References: Lalande et al., 2022 (EMIDEC, above). Wasserthal et al., TotalSegmentator, Radiology: Artificial Intelligence, 2023.

Stages (one semester each):

  1. Measure the errors. Run automatic outlining tools on the EMIDEC scans (first checking that each tool supports MRI) and measure overlap and distance against the expert outlines. Hand over error results for each patient and tool.

  2. Map where the errors are. Place the errors onto bull's-eye maps to show which parts of the heart wall are least reliable. Needs B1 Stage 1 to be finished first. Hand over the error maps and a summary report.

B3. From Body-Surface ECG to a Map of Heart Activity

Electrocardiographic imaging uses many electrodes on the chest, together with a body scan, to estimate the electrical activity on the heart surface. It is one of the non-invasive ways to find where VT starts. This project reproduces a standard method on public data and tests how sensitive it is to small errors.

Expected results: A reproduced reconstruction pipeline and a sensitivity analysis.

Learning outcomes: Inverse problems, numerical methods, working with linked signal and geometry data.

Suitability: CSI6900.

References: Aras et al., Experimental Data and Geometric Analysis Repository – EDGAR, Journal of Electrocardiology, 48(6):975–981, 2015.

Stages (one semester each):

  1. Explore the data. Set up an EDGAR account, list which datasets include VT recordings, and load and display the signals and heart geometry. Hand over a dataset list and loading scripts.

  2. Rebuild a standard method. Reproduce a standard reconstruction method and compare its output with measured heart signals where the data has them. Hand over the working reconstruction and the comparison.

  3. Sensitivity test. Measure how much small errors in electrode position change the result. Hand over the sensitivity analysis and report.

How the handoff works

Every stage ends with the same handoff package, so no student starts from zero.

  • Code in a shared repository, with a "Start here" guide explaining how to run everything from scratch.
  • A data download script, not copies of the data, so each student gets the data under its own license.
  • A results file listing the exact settings used, so the numbers can be reproduced.
  • A handoff note: what works, what doesn't, what was tried and dropped, and what the next stage should do first.

The incoming student's first task is to rerun the previous stage and get the same numbers before changing anything. This catches missing files or steps early.
